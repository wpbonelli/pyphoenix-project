# Backend Refactoring Plan

## Vision

Move from xattree's magic attribute proxying to explicit attrs-based components with xarray views.

**Core Principles:**
1. Attrs fields are primary storage (standard Python `__dict__`)
2. Protocols define capabilities (e.g., `DimensionProvider`)
3. Generic mixins handle dataset/tree conversion (keep autogenerated classes minimal)
4. `.data`/`.tree` properties are views built on-demand (share array references)
5. Single source of truth (no sync complexity)

## Architecture

```python
from flopy4.mf6.spec import dim, array
from flopy4.mixins import DatasetConvertibleMixin, TreeConvertibleMixin

# Leaf nodes: attrs fields + .data property
@define
class Dis(Package, DatasetConvertibleMixin):
    nlay: int = dim(coord=True, scope="model")
    delr: NDArray = array(dims=("ncol",), dtype=np.float64)
    # and .data property provided by DatasetConvertibleMixin

# Internal nodes: attrs fields + .tree property
@define
class Model(TreeConvertibleMixin):
    dis: Dis | None = None
    npf: Npf | None = None
    # and .tree property provided by TreeConvertibleMixin
```

## Migration Strategy

Go top down. Start with containers (simulation, model), then migrate packages one-by-one.

Containers define the interface contract (`.data` property). Both old xattree and refactored packages can satisfy this, allowing gradual migration without adapters.

## Refactoring Steps

### Phase 1: Foundation

#### 1.1 Move metadata system from `xattree`

The `flopy4/spec.py` module currently wraps `xattree` field decorators. These are fairly simple, they just encode metadata creation which will need to move here.

For instance, metadata keys: `"kind"`, `"dims"`, `"dtype"`, `"coord"`, `"scope"`.

Metadata can be stored directly at the top level now, instead of under a top-level key (previously "xattree").

The `flopy4/mf6/spec.py` module can continue to wrap the `flopy4/spec.py` module field decorators with MF6-scoped details, like block name.

#### 1.2 Define runtime-checkable protocols

Create `flopy4/protocols.py`:
- `DimensionProvider`: Components that declare dimensions
  - `get_dimensions() -> dict[str, int]`
  - `get_dimension_scope() -> str | type`
- `DatasetConvertible`: Components with `xr.Dataset` views under `.data`
  - `from_dataset(ds) -> Self` classmethod
- `DataTreeConvertible`: Components with `xr.DataTree` view under `.tree`
  - `from_datatree(tree) -> Self` classmethod

**Note**: Protocols define *interfaces*, mixins (see below) provide *implementations*.

#### 1.3 Build Generic Conversion Utilities
Create `flopy4/conversion.py`:
- `attrs_to_dataset(obj) -> xr.Dataset`
  - Introspects attrs fields reading metadata directly
  - Arrays → data_vars (shared references)
  - Scalars → attrs (copied)
  - Handles dims, coords via field metadata
- `dataset_to_attrs(cls, ds) -> obj`
  - Reconstructs attrs object from dataset
  - Uses class definition to know what to extract
- `attrs_to_tree(obj) -> xr.DataTree`
  - Recursively builds tree from object + children
  - Uses field metadata to identify child relationships

#### 1.4 Create Mixins
Create `flopy4/mixins.py`:
- `DatasetConvertibleMixin`: Provides implementation
  - `.data` property (calls `attrs_to_dataset(self)`)
  - `.from_dataset(ds)` classmethod (calls `dataset_to_attrs(cls, ds)`)
- `TreeConvertibleMixin`: Extends above
  - `.tree` property (calls `attrs_to_tree(self)`)
  - `.from_tree(tree)` classmethod
- Classes inherit mixins to get functionality automatically

### Phase 2: Container Refactoring

#### 2.1 Update Package Base Class
Refactor `flopy4/mf6/package.py`:
- Use `@define` with standard attrs fields
- Inherit `DatasetConvertibleMixin`
- Add `parent: Component | None` field
- Remove xattree decorator magic
- Keep minimal - let mixin handle conversion

#### 2.2 Update Model Base Class
Refactor `flopy4/mf6/model.py`:
- Use `@define` with standard attrs fields
- Inherit `TreeConvertibleMixin`
- Child packages as typed fields (e.g., `dis: Dis | None = None`)
- `.tree` property builds from children's `.data`
- Remove xattree decorator magic

#### 2.3 Update Simulation Class
Refactor `flopy4/mf6/simulation.py`:
- Use `@define` with standard attrs fields
- `models: dict[str, Model]` field
- `tdis: Tdis` field
- `.tree` property builds full hierarchy
- Add convenience: `.to_netcdf()`, `.from_netcdf()`

#### 2.4 Update Context
Refactor `flopy4/mf6/context.py`:
- Simplified context handling with new architecture
- Dimension registry integration

### Phase 3: Dimension System

#### 3.1 Dimension Registry
Create `flopy4/mf6/dimensions.py`:
- `DimensionRegistry` class
  - `register(component: DimensionProvider)`
  - `resolve(dim_name: str, scope: str | type) -> int | None`
  - `get_all_dims(scope: str | type) -> dict[str, int]`
- Scoping rules (model-level, global, etc.)
- Integration with component hierarchy

#### 3.2 Use Field Helper Functions
Use metadata helper functions in component classes:
```python
from flopy4.metadata import dim, array

# Simple and clean
nlay: int = dim(coord=True, scope="model")
delr: NDArray = array(dims=("ncol",), dtype=np.float64)

# Or for MF6-specific
from flopy4.mf6.metadata import array
delr: NDArray = array(dims=("ncol",), block="griddata", dtype=np.float64)
```

### Phase 4: Package Migration

Migrate packages one at a time, starting with simplest:

#### 4.1 Simple Packages First
- Packages with no dimension dependencies
- Minimal array fields
- Examples: `Tdis`, `Oc`, `Ic`

For each package:
1. Convert to `@define` with explicit attrs fields
2. Inherit `DatasetConvertibleMixin`
3. Use field helper functions (`dim()`, `array()`) for metadata
4. Implement `DimensionProvider` protocol if declares dimensions
5. Remove xattree decorator
6. Verify `.data` property works
7. Run existing tests (should pass with minimal changes)

#### 4.2 Dimension-Providing Packages
- Packages that declare model dimensions
- Examples: `Dis`, `Disv`, `Disu`

Additional steps:
1. Implement `DimensionProvider` protocol
2. Define `get_dimensions()` method
3. Register with dimension registry
4. Test dimension resolution

#### 4.3 Dimension-Consuming Packages
- Packages with arrays shaped by other components' dimensions
- Examples: `Npf`, `Sto`, `Chd`, etc.

Additional steps:
1. Add dimension validation in field validators
2. Hook into dimension registry for shape inference
3. Test array broadcasting and validation

### Phase 5: Testing & Validation

#### 5.1 Test Updates
- Update tests where API changes (should be minimal)
- Add tests for new patterns:
  - Direct field access
  - `.data` property usage
  - Dimension resolution
  - Tree building
  - Serialization round-trips

#### 5.2 Validation
- Verify no performance regressions
- Check memory usage (should improve - no dual storage)
- Ensure IDE/type-checker support works
- Validate serialization compatibility

### Phase 6: Cleanup

#### 6.1 Remove Old xattree Code
- Once all components migrated
- Remove xattree decorator
- Clean up unused proxy code

#### 6.2 Documentation
- Update docstrings for new patterns
- Example notebooks showing new API
- Migration guide for users (if applicable)

## Key Design Decisions

### Field Metadata System
- **No top-level namespace key**: Metadata stored directly at field level
- **Scoped by module**: Generic helpers in `flopy4/metadata.py`, code-specific in `flopy4/{code}/metadata.py`
- **Helper functions wrap attrs_field()**: Users call `dim()`, `array()`, etc. rather than constructing metadata dicts
- **Aliased imports**: MF6-specific helpers share names with generic ones, aliased on import if both needed
- **Metadata keys**:
  - Generic: `"kind"`, `"dims"`, `"dtype"`, `"coord"`, `"scope"`
  - MF6-specific: `"block"`, etc.
- **Extensible**: Conversion functions ignore unknown keys, allowing code-specific extensions

### Protocol vs Mixin Pattern
- **Protocols** (`flopy4/protocols.py`): Define interfaces for type checking and contracts
  - Example: `DimensionProvider`, `DatasetConvertible`
  - Runtime-checkable via `isinstance()`
- **Mixins** (`flopy4/mixins.py`): Provide reusable implementations
  - Example: `DatasetConvertibleMixin`, `TreeConvertibleMixin`
  - Inherit to get functionality automatically
- Components inherit mixins (implementation) and satisfy protocols (interface)

### Dimension Scoping
- Model-level: Dimensions visible within a model (e.g., `nlay`, `nrow`, `ncol`)
- Global: Dimensions visible across simulation (e.g., time dimensions)
- Resolution walks up parent chain when needed

### Array Storage
- Arrays stored directly as numpy arrays in `__dict__`
- `.data` shares array references (mutations visible in both)
- Scalars copied to dataset attrs (component fields are source of truth)

## Success Criteria

1. **Type safety**: IDE autocomplete and type-checkers work fully
2. **Debuggability**: Standard Python debugging, no magic attributes
3. **Performance**: No slowdown vs. current (likely faster)
4. **Compatibility**: Existing tests pass with minimal changes
5. **Flexibility**: Easy to add new serialization formats
6. **Clarity**: Code is self-documenting via attrs and protocols
