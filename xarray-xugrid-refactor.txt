  ---
  Plan: Return xu.UgridDataset from to_xarray(), remove ugrid properties

  Problem summary

  VertexGrid.to_xarray() and StructuredGrid._layered_mesh_dataset() each spend
  ~100 lines manually wiring UGRID CF attributes (mesh, mesh_node_x,
  mesh_face_nodes, cf_role, start_index, etc.) onto a plain xr.Dataset. That's
  exactly what xugrid exists to do — and the result is a plain xr.Dataset that
  loses spatial indexing. The separate ugrid properties then expose just the
  bare xu.Ugrid2d topology, which is low-level and forces users to rewrap it
  themselves (as the tests show).

  ---
  Step 1 — Refactor VertexGrid.to_xarray() → returns xu.UgridDataset

  Build xu.Ugrid2d from _topology() (already done in the ugrid property),
  construct the time coordinate and layer coordinate as an xr.Dataset, wrap it
  in xu.UgridDataset(ds, grids=ugrid2d). Delete all the manual mesh,
  mesh_node_x, mesh_face_nodes, etc. attribute assignments — ~120 lines removed.

  Step 2 — Refactor StructuredGrid._layered_mesh_dataset() → returns 
  xu.UgridDataset

  Same treatment for the LAYERED_MESH branch. The STRUCTURED branch
  (_structured_dataset()) stays as xr.Dataset — structured grids don't need
  xugrid.

  StructuredGrid.to_xarray() return type becomes xr.Dataset | xu.UgridDataset
  depending on netcdf_format.

  Step 3 — Remove the ugrid properties

  Both StructuredGrid.ugrid and VertexGrid.ugrid become redundant: users call
  grid.to_xarray() and get an xu.UgridDataset from which uds.grids[0] gives the
  xu.Ugrid2d if needed.

  Currently it does xr.merge([grid_ds, *pkg_dss]). xr.merge cannot accept
  xu.UgridDataset. For the UGRID path, instead:

  2. Collect all package xr.Datasets and merge them into a single xr.Dataset
  3. Combine via xu.UgridDataset(merged_pkg_ds, grids=grid_uds.grids) — or
  assign variables one by one

  Return type of NetCDFModel.to_xarray() becomes xr.Dataset | xu.UgridDataset.

  Step 5 — Update NetCDFModel.to_netcdf()

  Dispatch on return type:
  ds = self.to_xarray()

  Change the to_xarray() return type annotation from xr.Dataset to xr.Dataset |

  grid_uds = self._grid.to_xarray(netcdf_format=_fmt, modeltime=self._time)  #

  merged = xr.merge([grid_uds.dataset, *pkg_dss])

⏺ On mesh_face_xbnds/ybnds:

  These are not in the UGRID-1.0 specification. UGRID defines face geometry
  entirely through face_node_connectivity — the vertex-coordinate bound arrays
  are redundant, since they're just node_x[face_nodes] / node_y[face_nodes].
  What the old code was doing is applying the CF bounds convention (which is in
  CF-1.x, for coordinate variables like x and y) to face centroid coordinates.
  It's a reasonable extension but not required by UGRID, and MODFLOW 6 doesn't
  need them to read the file correctly.

  Critically, _topology() still computes x_bnds and y_bnds and returns them — we
   just stopped using them in _layered_mesh_dataset. If they ever turn out to be
   needed, they can be added back to the ds before wrapping in xu.UgridDataset:

  ds["mesh_face_xbnds"] = (["nmesh_face", "max_nodes"], topo["x_bnds"])
  ds["mesh_face_ybnds"] = (["nmesh_face", "max_nodes"], topo["y_bnds"])

  No xugrid interaction required — they'd live in the underlying xr.Dataset as
  plain data variables.

  ---
  On the projection boundary:

  The tension is that CRS is referenced in two separate places:

  1. _cf_var_attrs() in netcdf.py sets grid_mapping = "projection" on every data
   variable (npf_k_l1, etc.) — it hardcodes the string "projection" as the CRS
  variable name.
  2. The CRS variable itself must actually be named "projection" in the dataset,
   or that grid_mapping attribute is a dangling reference.

  If we passed crs=self.crs to xu.Ugrid2d, xugrid would write its own CRS
  variable when calling .to_netcdf() — but under a name it chooses (likely "crs"
   or using pyproj's CF encoding), not "projection". Then data variables would
  declare grid_mapping = "projection" (from _cf_var_attrs) but there'd be no
  "projection" variable, only xugrid's differently-named one.

  So the boundary is: we own the "projection" variable and all references to it;
   xugrid owns the topology variables and knows nothing about CRS naming.
  Collapsing that boundary would require auditing and updating _cf_var_attrs to
  use whatever name xugrid picks — a reasonable future cleanup, but out of scope
   here.
